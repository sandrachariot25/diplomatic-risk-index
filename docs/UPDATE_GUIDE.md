# Ежемесячное обновление DRI (сайт и монитор)

Обновлять раз в месяц, в первых числах (например, 5-го): к этому времени есть полный прошлый месяц GDELT.
Всё делается в папке проекта; интернет нужен только для шагов сбора. Ориентир по времени — 1–2 часа,
из них ручная работа — шаги 3–5.

## Что обновляется само (скрипты)

| Шаг | Команда | Источник | Задержка данных |
|---|---|---|---|
| 1. Новости | `python scripts/collect_gdelt_monthly.py --step 1 --workers 4 --execute`, затем `--monthly` | GDELT 1.0 | 1 день |
| 2а. Торговля | `python scripts/economic_trade.py`, затем `python scripts/features_econ_v2.py` | МВФ, Comtrade | 2 мес. |
| 2б. Рынки | `python scripts/collect_markets.py --execute` и `--set seafood --execute`, затем `features_rivalry_v2.py` | UN Comtrade | 2–3 мес. |
| 2в. Промпроизводство | `python scripts/fetch_industrial.py`, затем `features_material2_v2.py` | ОЭСР | 1–2 мес. |
| 2г. Рейтинги | `python scripts/fetch_approval.py`, затем `approval_v2.py` | Википедия (сводки опросов) | ~1 нед. |

## Что требует участия (в сессии с Claude)

3. **Стенограммы парламентов.** Сбор новых заседаний (`collect_kokkai_full.py --execute` для Японии;
   корейские стенограммы — тем же порядком, что и корпус) и разметка новых выступлений по кодбуку v2.2
   (`annotate_v2.py next` → разметка → `save`), затем `features_v2.py`. Стенограммы выходят с задержкой
   в несколько недель, поэтому последний месяц обычно неполный и дозаполняется в следующем обновлении.
4. **Реестр судов.** Проверить новости о решениях по принудительному труду и «женщинам для утешения»:
   добавить вынесенные решения в `data/court_rulings.csv`, назначенные даты — в `data/court_pipeline.csv`
   (поле `scheduled_date`). Затем `python scripts/courts_v2.py` и `python scripts/triggers_v2.py`.
   Это самый важный шаг: от него зависит оценка риска.
5. **Новые обострения.** `python scripts/episodes_v2.py` покажет, появился ли новый эпизод. Если да —
   эксперт определяет причину (лист в `data/dri_v2_episode_causes.xlsx`), публичный текст эпизода
   добавляется в `site/content.json` → `episodes`.

## Пересборка и публикация

6. `python scripts/causes_analysis_v2.py` → `python scripts/monitor_v2.py` → `python scripts/export_public_v2.py`.
   Скрипт выгрузки остановится с сообщением, если для нового повода, действия или эпизода нет английского
   текста в `site/content.json` — дописать и запустить снова.
7. Проверить сайт локально (конфигурация `dri-site`, http://localhost:8510) и опубликовать:
   закрытая ссылка claude.ai — повторная публикация `site/artifact.html`; открытый сайт — загрузить
   содержимое папки `site/public/` (index.html + data/) на хостинг (Netlify: перетащить папку в раздел Deploys).

8. Сохранить в GitHub (закрытый репозиторий github.com/sandrachariot25/diplomatic-risk-index):
   `git add -A`, `git commit -m "Обновление за <месяц>"`, `git push`. Что не попадает в репозиторий
   (полные тексты, разметка, бланки, сырые выгрузки), задано в `.gitignore` — эти файлы остаются только на компьютере.

## Почему оценка «на ноябрь» строится по октябрю
Индекс месяца считается, когда месяц закончился и данные собраны. Прогноз всегда смотрит на 3 месяца
вперёд от последнего полного месяца: по данным за октябрь — ноябрь–январь. Свежие события текущего месяца
(например, решение суда 7 ноября) попадают в календарь поводов сразу, как только их внесли в реестр судов.
